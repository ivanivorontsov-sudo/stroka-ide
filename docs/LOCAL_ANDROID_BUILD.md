# Локальная сборка Android-проектов на смартфоне

Строка передаёт Android-проект в отдельную ARM64-среду Termux и запускает Gradle непосредственно на смартфоне.

## Поддержка

- Android APK: `assembleDebug`
- Android App Bundle: `bundleDebug`
- Обычный Python-проект без Gradle: автоматическое создание Android-каркаса с Chaquopy
- Tkinter-подобный интерфейс: ограниченный совместимый слой «Строки» поверх Android WebView
- `requirements.txt`: установка пакетов с Android wheels Chaquopy
- Результаты: `Download/StrokaBuild/output/`
- Журнал: `Download/StrokaBuild/output/build.log`

Требуются Android 10+ и ARM64. Windows EXE и Linux ELF этим локальным сборщиком не поддерживаются. Для обычного Python-проекта сборщик автоматически создаёт Gradle/Android-проект, переносит Python-модули и ресурсы, добавляет Chaquopy и собирает APK.

Для Python/Tkinter поддерживается распространённый набор виджетов (окно, рамки, подписи, поля ввода, кнопки, переключатели, списки и переменные). Настольный Tkinter не запускается на Android как нативный Tk: интерфейс отображается через WebView. Геометрия `pack/grid/place` пока упрощённая, а произвольные desktop API и native-зависимости не превращаются автоматически в Android API.

## Язык «Понятный» 2.5 в редакторе

Файлы с расширением .pon распознаются как отдельный язык:

- подсветка ключевых слов, типов, констант и встроенных функций;
- автодополнение словаря языка и имён, встречающихся в проекте;
- запуск на телефоне через встроенный компилятор из репозитория https://github.com/ivanivorontsov-sudo/ponyatny, без Node.js и сети;
- подключение стандартных модулей стд/время, стд/консоль, стд/математика, стд/случай, стд/списки, стд/строки, стд/файлы и локальных файлов .pon из проекта;
- голосовой ввод автоматически переключается на русский. Поддерживаются ключевые слова, синонимы, числительные словами, арифметические операторы и названия скобок; команды редактора вроде сохранения и остановки микрофона остаются командами;
- полная справка по синтаксису открывается через меню редактора и может быть скопирована целиком;
- в шаблонах проектов есть готовый стартовый проект main.pon.

Код «Понятного» выполняется внутри редактора через JavaScript runtime компилятора в WebView. Это не означает, что .pon уже является самостоятельной целью сборки APK: упаковка отдельной программы на «Понятном» в APK пока не реализована.

## Первичная настройка

1. Установите Termux из одного источника — [официальные GitHub Releases](https://github.com/termux/termux-app/releases) или [F-Droid](https://f-droid.org/packages/com.termux/). Не смешивайте сборки из разных источников: у них разные подписи.
2. Откройте Termux вручную хотя бы один раз.
3. В «Строке» нажмите «Подготовить локальную сборку (Termux)». Если Android пока блокирует внешнюю команду, откройте Termux и выполните:
   `termux-setup-storage`, разрешите доступ к файлам, затем:
   `bash ~/storage/downloads/StrokaBuild/setup-termux.sh`
4. Скрипт установит JDK 17, Gradle, ARM64 AAPT2, apksigner и Android SDK API 36. Он также автоматически включит `allow-external-apps=true`; вручную редактировать `termux.properties` больше не нужно.
5. В настройках Android откройте приложения → Строка → разрешения → дополнительные разрешения и разрешите «Запуск команд в Termux» (`com.termux.permission.RUN_COMMAND`).
6. Вернитесь в «Строку», выберите Android APK или AAB и нажмите «Собрать APK / AAB прямо на телефоне».

## Почему Termux пока не находится внутри APK

Termux — отдельное Android-приложение со своим UID, подписью и закрытой папкой данных. Android не позволяет «Строке» встроить его APK как библиотеку или напрямую использовать его приватный rootfs. Официальная универсальная сборка Termux вместе с bootstrap занимает около 180 МБ. Поэтому Termux устанавливается как отдельное приложение, а «Строка» автоматически подготавливает и запускает в нём сборочную среду. Это ограничение Android-песочницы, а не прихоть сборщика.

## Как это работает

Строка архивирует исходники проекта (исключая .git, build, .gradle, node_modules и IDE-кэши), копирует архив, сборочный скрипт и Python runtime в общую папку Downloads/StrokaBuild через MediaStore и вызывает Termux RunCommandService. Termux распаковывает проект в собственный cache. Если находит Gradle Android-проект — запускает его сборку. Если Gradle-проект не найден, но найден Python-файл, автоматически создаёт Android-приложение, копирует Python-файлы и ресурсы, добавляет Chaquopy и совместимый Tkinter UI runtime, затем запускает Gradle. Для сгенерированного проекта используется Gradle 8.9 с проверкой SHA-256. Результаты и build.log сохраняются в Downloads/StrokaBuild/output.

Для ARM64 используется нативный Termux AAPT2 вместо x86_64-бинарника из Maven. Android command-line tools загружаются с официального домена Google, а SHA-256 архива проверяется до распаковки.

## Ограничения и безопасность

- Разрешение Android «Запуск команд в Termux» и настройка Termux для внешних команд — обязательные меры безопасности платформы. Скрипт может включить настройку внутри Termux только после того, как пользователь один раз запустит его из самого Termux.
- Локальная сборка использует debug-подпись. Для обновления уже установленного приложения нужна та же release-подпись, что и у исходной установки.
- Первая установка SDK и зависимостей может занять несколько гигабайт и продолжительное время. Не закрывайте Termux во время сборки.
- Проекты с неподдерживаемыми native host tools, проприетарными плагинами или нестандартной конфигурацией могут не собраться. Подробности будут в build.log.
- Chaquopy не включает системный Tkinter. «Строка» подменяет `tkinter` собственным совместимым слоем; это подходит для простых форм и калькуляторов, но не для сложных desktop-приложений, Canvas, оконных менеджеров и сторонних Tkinter-плагинов.
- Пакеты из `requirements.txt` должны иметь совместимые с Android wheels в репозитории Chaquopy. Пакеты, требующие неподдерживаемой нативной сборки, нужно адаптировать отдельно.
