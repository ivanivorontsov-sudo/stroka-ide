# Строка

Удобный редактор кода для Android-смартфона: подсветка 13 языков, панель символов над клавиатурой, свайп-курсор, голосовое программирование на русском и английском, запуск Python и JavaScript, просмотр HTML/Markdown, Git (JGit), шаблоны проектов и автосохранение.

## Голосовое программирование

Голосовой ввод понимает английские ключевые слова языков программирования и русские варианты распространённых конструкций. Поддерживаются команды редактора, знаки препинания и операторы, математические числа на русском и английском, а также стили идентификаторов:

- `camel case` → `userProfileName`
- `Pascal case` → `UserProfileName`
- `snake case` → `user_profile_name`
- `kebab case` → `user-profile-name`
- `flat case` → `userprofilename`

Примеры: `function greet open paren name close paren colon new line return name`, `console log open paren quote hello quote close paren`, `если ready двоеточие возврат истина`.

Для максимально надёжного распознавания английской речи выберите EN, для русской речи с английскими названиями кода — RU. Переключатель RU/EN задаёт язык акустического распознавателя; подсказки ключевых слов не делают модель полностью мультиязычной.

### Движки распознавания

- **Авто:** при подключённой сети используется системный распознаватель Android; без сети приложение пробует Android on-device (Android 12+), затем Vosk.
- **Android на устройстве:** отдельный офлайн-режим через `SpeechRecognizer.createOnDeviceSpeechRecognizer`. Требуются Android 12+ и поддержка выбранного языка системной службой.
- **Vosk:** полностью локальное распознавание после загрузки русской или английской модели через Настройки → Голосовой ввод.

Системному распознавателю передаются подсказки со словами команд и символов (Android 13+); приложение запрашивает до пяти вариантов распознанной фразы и выбирает вариант, похожий на известную команду.

**Конфиденциальность:** стандартный системный распознаватель может отправлять аудио на сервер провайдера — это зависит от службы устройства. Для обработки на телефоне выбирайте «Android на устройстве» (если доступен) или «Vosk».

## Голосовые блоки кода

Голосом можно попросить вставить готовый каркас: «нужна программа / кусок кода / блок кода для того, чтобы получить имя», «создай веб-форму», «сделай модальное окно», «добавь CSS-оформление», «подключи библиотеку requests». Шаблон выбирается по расширению и языку активного файла; PHP-файлы `.php` получают PHP/HTML-форму, а явное название языка в запросе может переопределить выбор. Для неизвестного формата без явно названного языка шаблон не вставляется, чтобы случайно не помещать Python в PHP, JSON и другие файлы.

Распознаются типовые блоки: ввод имени, HTML-форма обратной связи, диалоговое окно, HTML-страница, CSS-оформление, функция, старт программы и импорт библиотеки. Это детерминированные шаблоны, а не генерация произвольного приложения: неизвестная предметная задача не выдумывается. Для внешних пакетов шаблон показывает команду установки, но не устанавливает зависимость автоматически. Макросы «подключи/подключить библиотеку», «импортируй пакет» и «установи пакет» также вызывают блок импорта.


## Сборка программ на «Понятном» для разных систем

В GitHub откройте **Actions → «Понятный — сборка для всех систем» → Run workflow**. Укажите папку проекта и главный файл `.pon`. По умолчанию используется проверочный пример из `tools/fixtures/ponyatny/main.pon`.

Одна сборка подготавливает:
- **Android:** APK и AAB (WebView-оболочка с программой и встроенным интерпретатором);
- **Windows:** автономный EXE x64;
- **Linux:** автономные ELF x64 и ARM64;
- **macOS:** автономные исполняемые файлы Intel x64 и Apple Silicon ARM64;
- **Web:** HTML/JavaScript-приложение;
- **Node.js:** переносимый JS-файл.

Нативные настольные исполняемые файлы собираются Bun Compile с включённым runtime; поддерживаемые цели подтверждены документацией Bun: https://bun.sh/docs/compiler/executables. Android-сборка использует Gradle и Android SDK.

Локальная подготовка переносимой версии:
```bash
node tools/build-ponyatny.mjs путь/к/main.pon --target all --out dist
```
Нативные файлы можно собирать отдельно с `--target windows-x64`, `linux-x64`, `linux-arm64`, `macos-x64` или `macos-arm64` при установленном Bun. Android-проект создаётся в `dist/android-project`; его APK/AAB собираются Gradle.

**Ограничения:** Android и Web-оболочки запускают код в WebView; Node.js-ориентированные операции с файловой системой и системными API требуют адаптации под браузерную среду. Настольные EXE/ELF/macOS-файлы — консольные приложения, не GUI-инсталляторы и не подписанные/нотариально заверенные пакеты. Сборка macOS-файла не равна готовому .app-бандлу.
